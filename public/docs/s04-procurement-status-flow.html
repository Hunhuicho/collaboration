회신 방법

  1. 아래 검토자 칸에 이름과 소속을 적습니다.
  2. 각 항목에서 동의(Y) / 수정 필요(N) / 보류를 고르고 의견을 적습니다. N을 고르면 사유는 필수입니다.

04

미결 ① — PR / PO를 Cancelled로 만드는 트리거 결정 필요

원본 가이드에는 트리거가 비어 있습니다. 아래는 확정을 위한 제안이며, 이견이 있는 행을 지목해 주세요.

원본 가이드의 질문

취소를 언제, 누가 하는지 정의가 없습니다. 예를 들어:

  • 승인 전 · 입고 전 요청자가 직접 취소?
  • 결재자가 반려하면 자동 취소(반려 → 취소)?
  • PO 취소는 GR이 없을 때만? 부분 입고 후에도 가능?
  • 취소 권한은 누구에게 있고, 사유 입력은 필수인가?
제안

취소 트리거 · 권한 · 후속 처리

업무 단계별로 취소를 허용 / 합의 필요 / 불가로 나누고, 불가 구간은 다른 수단(잔량 종결, 대변전표)으로 처리하는 안입니다.

구분조건제안 트리거 · 처리권한후속 문서
PR결재 전 OP / SM / UA 취소가 아니라 상신 회수 후 삭제로 처리. CN을 쓰지 않음 요청자—
PR승인 후 · PO 없음 승인 완료, 연결 PO 없음 사유 입력 후 취소 → PR_STATUS = CN 요청자 또는 구매팀—
PR승인 후 · PO 있음 PR_STATUS = PO PR 단독 취소 불가. PO 취소가 선행되어야 하고, PO 취소 시 PR도 CN으로 연동 구매팀PO 취소 필수
PR반려 PR_STATUS = RJ 반려는 취소가 아님. RJ를 CN으로 자동 전환하지 않음 (미결 ② 참조) 결재자—
PO발주 직후 PO_STATUS = OP, GR 없음 구매팀 취소 → PO_STATUS = CN + 공급사 취소 통보 구매팀연결 PR → CN 또는 Open 복귀
PO공급사 확정 후 PO_STATUS = CF, GR 없음 공급사 합의 필요. 취소 요청 → 공급사 수락 후 CN 구매팀 + 공급사DN 있으면 DN 선(先) 취소
PO부분 입고 PO_STATUS = PD 전체 취소 불가. 잔량 종결(Close short)로 처리 — 입고분은 유효 구매팀미입고 잔량만 종결
PO송장 접수 후 IR_STATUS = OP / MC / PS 취소 불가. 반품 또는 대변전표(Credit Memo)로 처리 구매팀 + 회계AP 전표 연동
Cancel (CN)

승인된 문서를 업무 사유로 무효화. 이력은 남고 후속 진행은 중단

Reject (RJ)

결재선에서 반려. 재작업 대상이며 취소가 아님

Close

잔량을 더 받지 않고 종결. 이미 진행된 부분은 유효

Delete

결재 전 문서를 삭제. 이력 조회 대상 아님

공통 제안: 취소는 사유 코드 + 자유 입력을 필수로 하고, 취소 이력(누가·언제·왜)을 문서 이력에 남깁니다. 자동 취소는 두지 않고 모두 명시적 행위로 처리합니다.
05

미결 ② — 반려된 PR을 재사용할 수 있는가 결정 필요

PR 번호 체계, 감사 이력, 결재 재시작 방식이 함께 결정됩니다.

원본 가이드의 질문

PR이 반려되면 요청자가 같은 PR을 수정해 다시 상신(RJ → OP 복귀)할 수 있는지, 아니면 새 PR을 만들어야 하는지 정해야 합니다.

안동작장점유의점
A. 재사용 권장 RJ → OP 복귀 후 수정·재상신. 결재 이력은 회차(rev)로 누적 요청자 입력 반복 없음, 같은 번호로 추적, 반려 사유와 수정 내용이 한 문서에 남음 결재 이력을 회차 단위로 쌓는 구조가 필요. 재상신 시 결재선 재계산 규칙 필요
B. 신규 생성 반려된 PR은 종결 상태로 고정, 복사해 새 PR 생성 문서 1건 = 결재 1회로 단순. 감사 관점에서 명확 번호가 계속 늘어나고, 반려-재작성 이력이 문서 간에 흩어짐. 원본 연결(참조 필드) 필요
제안: A(재사용)를 기본으로 하되, 재사용 가능 횟수와 조건을 정합니다. 예 — 반려 후 영업일 N일 이내, 금액이 결재 기준 구간을 넘지 않는 수정이면 재상신 허용, 그 밖에는 신규 PR. 반려 사유는 필수 입력으로 두고 PR 이력에 회차별로 남깁니다.
