회신 방법

  1. 아래 검토자 칸에 이름과 소속을 적습니다.
  2. 각 항목에서 동의(Y) / 수정 필요(N) / 보류를 고르고 의견을 적습니다. N을 고르면 사유는 필수입니다.
  3. 입력하는 즉시 공유 공간에 저장됩니다. 상단 전체 응답에서 다른 분들의 회신도 볼 수 있습니다.

Cancelled (CN) 트리거 — 검토용 제안

현재 문서에는 CN이 "승인 이후 후속 업무 사유로 취소"로만 적혀 있고 발생 시점 · 권한 · 후속 처리가 없습니다. 아래는 확정을 위한 제안이며, 수정할 행이 있으면 회신란에 행 번호와 함께 적어주세요.

구분조건제안 트리거 · 처리권한후속 문서
PR결재 전 Draft / Submitted / In Progress 취소가 아니라 상신 회수 후 삭제로 처리. CN을 쓰지 않음 요청자—
PR승인 후 · PO 없음 PR APPR = A, 연결 PO 없음 사유 입력 후 취소 → PR_STATUS = CN. 사용자 상태는 Cancelled 요청자 또는 구매팀—
PR승인 후 · PO 있음 PR_STATUS = PO PR 단독 취소 불가. PO 취소가 선행되어야 하며, PO 취소 시 PR도 CN으로 연동 구매팀PO 취소 필수
PR반려 PR APPR = R 반려는 결재 상태이며 취소가 아님. CN으로 자동 전환하지 않음 결재자—
PO발주 직후 PO_STATUS = OP, GR 없음 구매팀 취소 → PO_STATUS = CN + 공급사 취소 통보 구매팀연결 PR → CN 또는 Open 복귀
PO공급사 확정 후 PO_STATUS = CF, GR 없음 공급사 합의 필요. 취소 요청 → 공급사 수락 후 CN 구매팀 + 공급사DN 존재 시 DN 선(先) 취소
PO부분 입고 PO_STATUS = PD 전체 취소 불가. 잔량 종결(Close short)로 처리하고 상태는 FD 또는 별도 Closed 사용 구매팀미입고 잔량만 종결
PO송장 접수 후 IR_STATUS = OP / MC / PS 취소 불가. 반품 또는 대변전표(Credit Memo) 프로세스로 처리 구매팀 + 회계AP 전표 연동
Cancel (CN)

승인된 문서를 업무 사유로 무효화. 이력은 남고 후속 진행은 중단

Reject (R)

결재선에서 반려. 결재 상태이며 업무 상태가 아님

Close

잔량을 더 받지 않고 종결. 이미 진행된 부분은 유효

Delete

결재 전 문서를 물리/논리 삭제. 이력 조회 대상 아님

DISPLAY LEVELItem Level

이 섹션의 사용자 상태는 모두 PR·PO 아이템 단위로 판정·표시됩니다.

CALL CONTEXTStatus shown when a user views a Purchase Requisition
Normal Progress

정상 흐름 12단계와 각 단계로 넘어가는 업무 이벤트입니다.

STEP 01

PR Draft

Changes when

The requester saves the PR without submitting it.

STEP 02

PR Approval in Progress

Changes when

The requester submits the PR and the PR approval process begins.

STEP 03

Approved / PO Pending

Changes when

Final PR approval is completed, but Purchasing has not created a PO.

STEP 04

PO Approval in Progress

Changes when

Purchasing creates a PO and its approval process is underway.

STEP 05

Ordered

Changes when

The PO is approved and issued to the supplier.

STEP 06

Supplier Confirmed

Changes when

The supplier confirms that the order has been received and accepted.

STEP 07

In Transit

Changes when

A shipment notice or delivery note is received for the order.

STEP 08

Partially Received

Changes when

Some, but not all, of the ordered quantity is received.

STEP 09

Received

Changes when

The full ordered quantity is received.

STEP 10

Invoice Received

Changes when

The supplier invoice is received.

STEP 11

Invoice Matched

Changes when

The invoice successfully passes the three-way match.

STEP 12

Completed

Changes when

The invoice is posted to Accounts Payable.

Exception Statuses

정상 구매 흐름을 중단시키는 예외 상태입니다.

EXCEPTION

PR Rejected

Changes when

A PR approver sends the purchase requisition back instead of approving it.

EXCEPTION

PO Rejected

Changes when

A PO approver sends the linked purchase order back instead of approving it.

EXCEPTION

Invoice On Hold

Changes when

The invoice fails the three-way match and requires review.

EXCEPTION

Cancelled

Changes when

An approved PR or PO is cancelled due to a later business decision.

05

PR / PO Modification Workshop PR 수정 기준

카드마다 개별로 Y/N과 의견을 받습니다. 수정 시점·재승인·후속 문서 통제를 확정합니다.

WORKSHOP SCOPE

PR Modification

승인된 PR을 수정하고 그 변경을 연결된 PO까지 반영하는 핵심 규칙을 확정합니다.

WORKING ASSUMPTION

현재 제안: 공급사가 Delivery Note를 등록하기 전까지 수량(Quantity)과 RDD만 수정 허용.

REVIEW REQUIRED

PR 수량 증가는 구현 전에 정책 검토가 필요합니다. 이미 확정된 PO와 PR 재승인 사이에 상태 충돌이 생깁니다. 논의용 대안: 추가 수량은 신규 PR로 생성.

01Reconfirm

1. Modification Window

공급사가 Delivery Note를 등록하기 전까지 PR 수정을 허용합니까? PR과 연결 PO를 잠그는 정확한 DN 이벤트를 확정해야 합니다.

02Reconfirm

2. Editable Fields

수정 가능 필드는 수량(Quantity)과 RDD(희망 납기일) 뿐입니까? 승인 후에도 열려 있어야 할 다른 필드가 있는지 확인이 필요합니다.

03Reconfirm

3. Quantity Decrease

수량 감소의 경우, 재승인 없이 PR 수정 → 연결 PO 갱신 → 수정된 PO 재발송까지 시스템이 처리해도 됩니까?

04Decision

4. Quantity Increase

수량 증가는 재승인이 필요하지만, 승인 진행 중에 공급사가 출하하거나 DN을 등록할 수 있습니다. 추가 수량은 신규 PR로 처리해야 할까요?

05Risk

5. Status during Reapproval

증가된 PR 수량이 재승인 중일 때 기존 PO는 이미 Supplier Confirmed일 수 있습니다. 사용자에게는 'PR Change Approval in Progress'를 보여주고, 승인 후 수정 PO는 Open으로 되돌려 공급사 재확인을 받는 안입니다.
